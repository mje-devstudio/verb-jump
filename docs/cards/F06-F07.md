# 작업 카드 — F06 · F07 밟기와 능력 모듈 (로컬 초안)

- **목표**: 동사 적을 밟으면 그 동사의 능력을 얻고, 능력 6개를 같은 틀의 모듈로 만든다.
- **완료 기준**
  - F06: 위에서 밟으면 능력 획득, 옆에 닿으면 피격. 얻는 순간 단어 카드(단어·발음·뜻·예문)를 1~2초 띄우고 TTS로 읽는다.
  - F07: 공통 틀(얻을 때·매 프레임·동사 버튼 입력·잃을 때)을 따르는 climb, float, break, sleep, dance, brake 6개. 새 동사는 데이터와 모듈 하나로 추가.
- **책임 / 검토**: 셀리아(구현) / 베스퍼(같은 세션이라 "자기 점검")
- **브랜치**: `F06-F07-stomp-abilities` ← `F05-lab-airtime`(6ca14ef) ← `main`(f149172). 아직 `main`에 합치지 않아 F05 수정 위에 쌓았다.
- **제외 범위**: 코인 흘리기·생명(F26), 시계 표시(F09), Tiled 맵(F08), 모바일 동사 버튼(F10), 도트(F12)

### 판단 기록

- **밟기 판정은 직전 발 위치로**: PRD는 "윗면 4px 아래까지"인데, 최대 낙하 속도(320px/s)에서는 한 스텝에 5.3px를 떨어져 현재 위치로만 보면 밟기를 놓친다. 그래서 "직전 스텝 발이 윗면 4px 아래보다 위였는가"로 판정한다.
- **금 간 벽은 작업용 맵에서만 부순다**: 레벨 원본은 그대로 두고 `World.map`(복사본)만 바꾼다. `mapVersion`이 바뀔 때만 렌더러가 타일을 다시 그린다.
- **능력용 틈 표시**: float로만 건너는 넓은 틈은 레벨 점검이 '구멍 착지'로 경고하므로 `abilityGaps`로 의도된 틈을 표시한다. 표시하지 않으면 경고가 나는지도 테스트한다.
- **이슈 003**: [옆에서 맞았는데 오답 동사를 얻는다](../issues/003-knockback-stomp.md) — 브라우저 점검에서 발견, 재현 테스트 → 수정 → 재발 방지.

### 미검증·남은 것

- **동사 콘텐츠 검수 전**: climb·float·sleep·dance의 뜻·발음·예문은 초안이다(break·brake만 PRD 값). P0 "학습 콘텐츠 검수"에서 사전과 대조해야 한다.
- **브라우저에서 확인하지 못한 것**: climb·float·break·오답 3종을 실제 루프에서 써 보는 것. 미리보기 패널이 숨겨져 rAF가 멈춰 있었다. 단위 테스트로만 확인했다.
- TTS 실제 소리 미확인(`speechSynthesis` 호출까지만).
- 피격 시 코인·생명 처리는 F26, 시계 벌칙 표시는 F09.
- `useGameStore` 훅 테스트(React Testing Library)는 F09에서 붙인다. 지금은 저장소 단위 테스트만 있다.
- 맵 가장자리 벽을 climb로 오르면 맵 위로 나갈 수 있다. 레벨 설계(F08)에서 가장자리 근처에 climb 구간을 두지 않거나 천장을 둔다.
