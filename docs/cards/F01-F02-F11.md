# 작업 카드 — F01 · F02 · F11 스테이지 API·재시도, 지연·실패 재현, 결과 화면 (로컬 초안)

- **목표**: 스테이지를 API로 받아 시작하고(실패하면 안내·다시 시도), 지연·실패를 화면에서 재현하며, 클리어하면 결과 화면을 보여 준다.
- **완료 기준**
  - F01: `GET /api/stages/commute`로 맵 주소·동사 데이터를 받는다. 도트 로딩 바, 실패하면 안내와 다시 시도. 자동 재시도 1회.
  - F02: 지연(0·1·3초)과 실패(끄기·50%·항상)를 화면에서 바꾸고 `delay`·`fail` 쿼리로 서버리스 함수에 전달.
  - F11: 점수(코인·철자·시간), 출근 시각, 정시·지각 도장, 완성한 철자 단어, 배운 동사, 잘못 쓴 동사 복습. 다시 하기는 같은 스테이지로.
  - 테스트(PRD): 1번 실패 → 자동 재시도로 성공, 2번 실패 → 안내와 다시 시도 버튼, 3초 지연 → 로딩 바(MSW).
- **책임 / 검토**: 다리안(API)·셀리아(화면) / 베스퍼(같은 세션이라 "자기 점검")
- **브랜치**: `F01-F02-F11-stage-api-result` ← `F09-F26-F27-hud-coins-letters`(86176b4)
- **제외 범위**: 랭킹·이니셜(F18), 말하기 보너스(F28), 실제 Vercel 배포(F13), 에러 바운더리(F13), Motion 화면 전환
- **외부 연결**: Vercel 서버리스 함수는 로컬에서 Vite 미들웨어로 같은 핸들러를 실행한다. 실제 Vercel 환경은 F13에서 확인(미검증).
- **현재 단계**: 검토(자기 점검 완료, 독립 검증 미실행)

### 판단 기록

- **API 핸들러는 Web 표준으로**: Vercel 함수와 로컬 Vite 미들웨어, 단위 테스트가 같은 `handleGetStage(request, deps)`를 부른다. 지연·난수는 `deps`로 넣어 테스트가 실제로 기다리지 않는다.
- **API 테스트는 `test/api/`에**: Vercel은 `api/` 안의 파일을 모두 함수로 배포하므로 테스트 파일을 밖에 둔다. `_lib`처럼 `_`로 시작하는 폴더는 함수가 되지 않는다.
- **응답 검증**: 서버 응답을 `parseStageData`로 하나씩 확인한다(Zod 같은 새 라이브러리 대신 맵 로더와 같은 방식). 형식이 틀리면 시작하지 않고 안내한다(테스트 포함).
- **능력 id를 shared로**: 서버(스테이지 데이터)가 게임 코드에 기대지 않도록 `ABILITY_IDS`를 `shared/rules/abilities.ts`로 옮겼다.
- **최고 기록**: 랭킹 규칙(점수 높은 순, 같으면 출근 시각 빠른 순)과 같은 비교로 이 기기에만 저장한다. 서버 랭킹은 F18.

### 미검증·남은 것

- **실제 Vercel 실행**: Web 표준 핸들러(`export function GET`)가 Vercel에서 그대로 도는지는 F13 배포 때 확인한다.
- 개발 모드 StrictMode 이중 마운트로 첫 스테이지 요청이 한 번 취소된다(브라우저 기록에 상태 0). 배포 빌드에서는 한 번만 요청한다.
- 타이틀의 소리·조용 모드, 효과음·발음 켜기/끄기는 아직 없다(보스전 F15·F16과 함께).
- Motion 화면 전환, 에러 바운더리(F13), 이니셜·랭킹(F18), 말하기 보너스(F28)는 범위 밖.
- 결과 화면의 실제 점수는 순간이동으로만 확인했다. 실제로 한 판을 끝까지 했을 때의 점수·시간은 플레이테스트에서 확인한다.
