# 이슈 002 — 높은 발판 달려 뛰기 거리가 실험실보다 1프레임(1.5px) 길다

- 발견: 2026-10-18, F04·F05·F25 자기 점검 중 측정값 비교
- 영향: 레벨 설계 규칙의 착지 거리와 게임의 실제 착지 거리가 1프레임 어긋남. 실험실에서 안전하다고 본 배치가 게임에서는 다를 수 있음

## 재현

땅 위 3칸 발판 끝에서 최고 속도 90px/s로 달리며 점프·방향키를 계속 누른다.

| 출발 높이 | 실험실(1/60초)    | 게임(수정 전)     |
| --------- | ----------------- | ----------------- |
| 평지      | 51.0px · 34프레임 | 52.5px · 35프레임 |
| 3칸       | 60.0px · 40프레임 | 61.5px · 41프레임 |
| 6칸       | 67.5px · 45프레임 | 69.0px · 46프레임 |

## 원인 조사

가설을 하나씩 로그로 확인했다.

| 가설                                                         | 확인                                       | 결과                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 버튼을 누른 다음 프레임에 점프가 시작된다(입력 지연 약 17ms) | 입력 프레임과 vy가 음수가 된 프레임을 기록 | 둘 다 0번 프레임. **입력 지연 없음**                                                                   |
| 거리를 누른 프레임부터 센다                                  | 출발 x와 점프 프레임 직전 x 비교           | 같은 값. 세는 방식 차이 아님                                                                           |
| 이동 계산 방식이 다르다                                      | 같은 맵에서 방식만 바꿔 측정               | **원인.** 앞뒤 속도 평균(사다리꼴)이면 41프레임, 속도 먼저·위치 다음(semi-implicit Euler)이면 40프레임 |

처음 구현은 속도 먼저·위치 다음이었는데, 최고 높이가 42.75px로 PRD 테스트 계획의 "약 45px"보다 낮게 나와 앞뒤 속도 평균으로 바꿨다. 그 결과 높이는 45.13px로 맞았지만 공중에 1프레임 더 머물러 거리가 늘었다. PRD의 45px·7px는 연속 공식 값이고, 레벨 규칙 거리는 1/60초 시뮬레이션 값이라 두 기준이 서로 다른 계산에서 나온 것이 근본 원인이다.

## 수정

- `stepPlayer`를 실험실과 같은 semi-implicit Euler로 되돌림(수치 `tuning.ts`는 그대로).
- 테스트 기준을 1/60초 시뮬레이션 값으로 고정: 최고 높이 42.75px, 짧은 탭 6.30px, 달려 뛰기 51.0/60.0/67.5px와 34/40/45프레임.

## 재발 방지

- `levelCheck.test.ts`가 0·3·6칸 거리와 프레임 수를 실험실 값과 정확히 비교한다. 계산 방식이 바뀌면 바로 실패한다.
- 기준값은 "연속 공식"인지 "1/60초 시뮬레이션"인지 반드시 같이 적는다.
- 레벨 점검 높이는 맵 바닥이 아니라 땅 윗면부터 센다(`groundRow`, `heightTiles`).
